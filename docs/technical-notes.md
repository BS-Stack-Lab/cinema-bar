# 개발·운영 참고

[서비스 소개와 시작 방법은 README에서 확인하세요.](../README.md)

현재 구현의 저장 방식, 조회 경로, 검증 절차와 알려진 제한을 정리한 기술 문서입니다. 일반적인 사용은 README만 읽어도 시작할 수 있습니다.

CGV·Megabox·롯데시네마의 극장, 정확한 작품 제목, 한국 상영일, 포맷을 감시하는 개인 메뉴바 앱입니다. 새 예매 가능 상영은 **앱 팝업을 먼저 표시한 뒤** 선택 연결한 Discord로 보냅니다. 웹훅이나 OS 암호화 저장소 없이도 앱 알림을 사용할 수 있습니다. 중앙 서버나 공용 계정은 필요하지 않습니다.

Node.js 22.12 이상과 npm을 사용합니다. `npm ci` 후 `npm run build`로 현재 호스트용 Electron 앱을 만드세요. macOS 앱은 `release/Cinema Bar-darwin-arm64/Cinema Bar.app`(Intel은 x64)에 있습니다. 미서명 로컬 패키지이며 배포용 서명·공증은 포함하지 않습니다. 개발 실행은 `npm run dev`입니다. 개발 Electron은 OS 로그인 항목에 등록되지 않습니다.

트레이를 누르면 440px 창을 열거나 숨깁니다. 상단 Cinema Bar 헤더를 드래그하면 열린 창을 이동할 수 있으며 탭·입력·버튼은 그대로 사용할 수 있습니다. 숨겼다 다시 열면 메뉴 아이콘 또는 커서가 있는 화면에 맞춰 다시 배치하며, 이동 위치를 저장하지 않습니다. 메뉴 위치가 확인되지 않으면 macOS Dock의 Cinema Bar를 눌러 숨겨진 창을 다시 열 수도 있습니다. 메뉴 위치가 확인되면 Dock 아이콘을 숨깁니다. 창 닫기는 감시를 유지합니다. 하단 전원 버튼이나 트레이 메뉴의 **앱 종료**가 프로세스와 감시·팝업을 끝냅니다. 다중 실행은 하나로 합칩니다.

1. **감시 목록**에서 영화관 → 지역 → 극장을 선택하고 작품 제목을 검색하세요. 애니메이션도 공식 예매 목록에서 부분 제목으로 찾을 수 있습니다. 검색 결과의 작품을 직접 선택한 뒤 상영일·포맷을 저장하세요. 검색어를 바꾸면 작품을 다시 선택해야 합니다. 지역을 바꾸면 극장만 초기화하고, 영화관을 바꾸면 극장·작품 선택을 모두 초기화합니다.
2. 첫 성공 조회부터 조건에 맞는 이미 예매 가능한 상영도 알립니다. 기존 버전이 조용한 기준선으로 저장했던 상영도 다음 성공 조회에서 목적지별 미처리 회차를 알립니다. 같은 상영을 여러 규칙이 찾거나 규칙을 수정해도 목적지별 중복 기록이 남아 있으면 다시 알리지 않습니다.
3. **설정 → 앱 알림**은 기본 켜짐입니다. 앱이 실행 중일 때 화면 우측 상단에 최대 3개의 작은 팝업을 표시하고 8초 후 닫습니다. 다른 창의 포커스를 빼앗지 않으며 기본 창 닫기 버튼으로 직접 닫을 수도 있습니다. OS 알림센터에는 전달하거나 기록하지 않습니다.
4. Discord도 받으려면 채널 설정 → 연동 → 웹후크에서 직접 만든 주소를 **설정**의 비밀번호 필드에 입력하세요. safeStorage 암호화가 필요하며 저장 후 원문을 UI·로그·snapshot에 내보내지 않습니다. OS 암호화가 없으면 Discord 저장·전송만 사용할 수 없습니다.

조회 간격은 기본 120초, 60~3600초입니다. 실패를 매진이나 상영 없음으로 처리하지 않습니다. HTTP 429의 Retry-After와 지수 backoff를 수동 갱신·재시작 후에도 지킵니다. 알려지지 않은 포맷은 특정 포맷 규칙과 일치하지 않으며 `모든 포맷`에서는 포함될 수 있습니다.

CGV는 현재 공개 BFF `https://cgv.co.kr/api/v1/booking/searchMovScnInfo`에 극장·상영일을 전송합니다. CGV에만 전용 메모리 Electron 44.9.1 `session.fetch`를 사용하고 cookie·Authorization·API key 없이 `credentials: omit`, `cache: no-store`, redirect 거부, 15초 제한으로 조회합니다. 2026-10-20 진단에서는 이 경로의 Chromium 조회가 HTTP 200이었고 같은 BFF의 Node fetch와 이전 backend 직접 호출은 제한되었습니다. 서버의 구체적인 차단 원인은 단정하지 않습니다. Megabox·롯데는 Node fetch를 유지합니다. 공식 서비스 변경·지역·네트워크에 따라 조회는 다시 실패할 수 있습니다.

CGV 실제 식별자는 극장·상영일·관 번호·상영 순번을 모두 포함합니다. `cntlYn=N`, 양수 `frSeatCnt`, 미래 한국 시작 시각이 모두 맞을 때만 예매 가능으로 판단합니다. 24:00~29:59는 다음 날 시각이며 원래 상영일을 유지합니다. 이미 저장한 전날 CGV 규칙은 한국 05:59까지 조회하고 06:00부터 만료합니다. 새 과거 날짜 입력은 허용하지 않습니다. 예매 링크는 현재 공식 `https://cgv.co.kr/cnm/movieBook/movie`를 사용합니다.

새 알림과 기준선은 원자적으로 디스크에 함께 저장합니다. 앱 팝업과 Discord는 독립된 큐·중복 기록을 사용합니다. 팝업 표시 완료 또는 실패 결과 뒤에 Discord를 시도하며 팝업 실패는 Discord를 막지 않습니다. 앱 알림은 표시 호출 전에 시도 기록을 저장하므로 **기록과 표시 사이에서 앱이 중단되면 해당 팝업을 놓칠 수 있습니다(at-most-once attempt)**. Discord 재시도·재시작은 팝업을 반복하지 않습니다. Discord는 429와 일시 오류를 최대 8회 재시도하고 401/403/404는 웹훅 교체를 기다립니다. 외부 응답이 불명확하면 같은 Discord 알림이 다시 도착할 수 있습니다(at-least-once).

양쪽 큐는 각각 100개·24시간, 이력은 최근 100개입니다. 앱 팝업은 한 전달 주기에서 최대 10개를 시도하며 남은 대기는 다음 주기에 이어집니다. 일반 회차의 목적지별 중복 기록은 30일·최대 5000개를 보존합니다. 날짜 그룹의 완료 기록은 같은 범위의 저장 감시와 미래 상영일이 남아 있으면 선택 버튼이나 감시를 꺼도 보존합니다. 앱 팝업 요청·실패와 Discord 결과를 구분해 표시합니다. 전체 일시 정지·절전·오프라인은 조회와 전달을 멈추며 공급자·Discord 속도 제한에 따라 전달이 지연될 수 있습니다. 규칙 수정·삭제는 관련 양쪽 대기를 취소합니다. 웹훅 교체·삭제는 Discord 대기만, 앱 알림 끄기는 로컬 대기만 취소합니다. 앱 알림을 다시 켜거나 웹훅을 추가하면 다음 적격 성공 조회에서 해당 목적지에 아직 처리 기록이 없는 현재 예매 가능 상영을 알릴 수 있습니다.

패키지 첫 실행은 로그인 후 자동 시작을 켜며 설정에서 끈 선택을 유지합니다. 절전 복귀·네트워크 복구 시 한 감시 흐름으로 이어갑니다. 로그인 전 부팅 직후 실행은 보장하지 않습니다. OS 사용자별 Electron `userData`에 저장하며 schema1은 검증 후 schema2로 원자 변환하고 원본 백업을 남깁니다. 기존 비CGV 규칙·상태·암호문은 보존합니다. CGV는 식별자가 변경되어 이전 대기를 이유와 함께 종료하고 다음 성공 조회부터 현재 예매 가능한 미처리 상영을 알립니다. 이번 첫 조회 알림 변경에는 프로필 초기화나 추가 저장 형식 변환이 필요하지 않습니다. 복구 가능한 기존 비CGV Discord 대기는 로컬 표시를 먼저 시도합니다. 미래 형식·잘못된 필드·변환 쓰기 실패는 원본을 보존하고 감시를 중단합니다. 손상된 주 파일은 마지막 유효 백업으로 복구하며 둘 다 손상되면 명시적 복구 초기화를 기다립니다.

`public/projector.svg`는 원본 픽셀 영사기입니다. `npm run icons:generate`로 원본 경로·색을 charcoal 둥근 배경과 여백 위에 정수 배율로 합성해 `assets/appIcon.png`(1024), `.icns`, `.ico`를 만듭니다. 기존에 고정한 Electron·Node만 사용하며 새 의존성이 없습니다. 격리 렌더러의 네트워크와 개인 프로필 접근은 금지됩니다. 작은 이미지는 nearest-neighbor로 축소합니다. 기본 build는 체크인 자산을 사용하며 아이콘을 자동 생성하지 않습니다. `npm run icons:check`는 임시 재생성과 바이트 비교, 컨테이너/크기, 실제 macOS Info.plist가 참조하는 ICNS의 1024 PNG와 master 일치를 검사합니다. 별도로 실행할 때도 먼저 `npm run build`가 필요합니다.

로컬 자동 검사는 다음과 같습니다. 실조회 진단은 아래 별도 설명을 확인한 뒤 실행하세요.

```sh
npm run format:check
npm run lint
npm run test
npm run build
npm run icons:check
npm run test:desktop
```

단위·통합·UI 테스트는 고정 fixture와 mock 공급자·시계·알림·Discord·로그인 adapter를 사용합니다. 공개 CGV 41행의 최소 필드 fixture는 parser 계약만 검증하며 실제 네트워크 성공 증거로 취급하지 않습니다. `test:desktop`은 macOS 패키지를 첫 실행 전에 임시 복제하고 별도 `dev.cinemabar.verification` ID·`Cinema Bar Verification` 표시명과 일관된 helper ID로 실행합니다. 원본 canonical 번들의 해시 보존, 두 프로세스의 검증 ID·임시 프로필·메모리 전용 암호화 codec을 확인하고 복제본과 프로필을 종료·오류 때 정리합니다. 실제 Keychain을 호출하지 않습니다. 기존 UI·트레이·IPC·단일 인스턴스 회귀, 헤더 drag CSS·컨트롤 경계와 통제된 **실제 앱 팝업**의 캡처·보안·포커스 유지·화면 경계·최대 개수·취소·자동 닫기를 검사합니다. 창 재열기는 표시 여부를 검사하고 foreground 포커스 관측은 별도로 기록합니다. PNG/JSON은 `CINEMA_SMOKE_OUTPUT`(기본 `release/smoke`)에 저장합니다. 아이콘 증거도 이 변수를 쓰며 기본값은 `release/icon-check`입니다.

선택적 공개 네트워크 진단 명령은 `npm run test:live`와 `npm run test:catalog-live`입니다. 특히 `test:live`는 아래에 설명한 레거시 정책 제한이 있어 현재 날짜별 알림의 통과 기준으로 사용하지 않습니다.

`test:live`(동일 명령 `probe:providers`)는 런타임 설치 확인과 compile 후 독립 Electron 진입점을 실행합니다. 실행 시작의 한국 오늘·다음날 최대 2개 날짜의 공개 시간표에서 CGV 0013·Megabox 1372·롯데 1016의 실제 예매 가능 작품을 선택하고 같은 실제 adapter로 Engine 첫 성공 조회의 앱 알림 요청과 두 번째 조회의 중복 방지를 검증합니다. 실제 팝업·Discord 대신 mock 목적지를 사용하며, 첫 조회는 적격 회차를 최대 10개 요청하고 두 번째는 이미 요청한 회차를 제외한 새 회차·이전 배치의 남은 대기를 최대 10개 요청해야 합니다. 롯데는 실제 catalog의 정확한 작품 코드로 `GetPlaySequence`까지 호출합니다. 공급자 하나라도 실패하거나 0개·catalog만 성공이면 전체 명령은 실패합니다. fixture·재생을 실제 조회로 표시하지 않으며 자연 발생 신규 상영을 기다리지 않습니다. 이 선택적 진단은 기존 회차별 배치 기대를 사용하는 레거시 도구이며, 이번 날짜별 그룹 정책에 맞춰 갱신하거나 실행하지 않았습니다. 날짜 그룹 동작은 단위·통합 테스트와 격리된 실제 앱 팝업 smoke로 검증합니다. 결과에는 시간·공개 요청 수/HTTP 결과·정규화 상영·두 Engine 상태·목적지별 mock 요청 회차를 기록합니다. `CINEMA_LIVE_OUTPUT`의 기본값은 `release/live`입니다.

`test:catalog-live`는 같은 격리 런처의 고정 카탈로그 모드로 세 공식 목록의 전체 지역·극장·작품, 유일 ID와 지역 참조, 두 지역 선택과 실제 애니메이션 제목 검색을 검증합니다. 비서울 MEGABOX 극장은 지역 코드를 생략한 실제 시간표에서 예매 가능 상영을 확인합니다. 결과는 `CINEMA_CATALOG_OUTPUT`(기본 `release/catalog`)의 별도 JSON에 저장합니다. 카탈로그 단위 fixture는 공개 응답의 최소 필드만 담고 실제 네트워크 증거를 대신하지 않습니다.

모든 검증은 개인 프로필·실제 Discord·OS 로그인 항목 쓰기·OS 알림 권한 변경을 사용하지 않습니다. 검증한 실행 범위는 macOS 호스트의 미서명 로컬 패키지입니다. PNG/ICO 구조 검사는 다른 OS 실행 검증을 뜻하지 않습니다. 실제 로그인 후 자동 시작·기기 절전/재부팅·Windows/Linux 실행은 별도 환경에서 확인해야 합니다. 외부 Discord 수신은 개인 환경에서 별도 실전송으로 확인하며 자동 검사 결과와 구분합니다. 개인 웹훅을 저장소·`.env`·Vite 변수·공유 스크린샷에 넣지 마세요.

공식 목록은 공급자별 메모리에 15분 동안, 같은 한국 날짜 안에서만 캐시합니다. **목록 새로고침**과 오류의 **재시도**는 캐시를 우회하며, 실제 갱신은 최소 10초 간격과 공급자의 429 대기 시간을 지킵니다. 목록에 아직 없는 작품은 나중에 다시 확인하세요. 이미 저장한 수동 규칙은 원래 극장·작품 식별자를 유지하며 날짜·포맷·활성 여부를 편집할 수 있습니다. **극장·작품 다시 선택**을 누르면 새 공식 선택이 필요합니다.

macOS canonical bundle ID는 `dev.cinemabar.desktop`입니다. 기존 `local.cinemabar.desktop` ID의 메뉴 호스팅 문제를 분리하며, 제품명·실행 파일명 `Cinema Bar`와 기존 `appData/Cinema Bar` 저장 경로·규칙·설정·웹훅 암호문 및 production safeStorage 경로를 유지합니다. 미서명 로컬 패키징 정책도 유지합니다. 정상 macOS 패키지만 준비 이벤트 전에 기존 저장 경로를 고정하며 개발 실행과 검증 임시 프로필은 덮어쓰지 않습니다.

지연 관측에서도 트레이 좌표가 연결 화면 상단 메뉴 영역 안에 놓이지 않으면 앱에 안내를 표시하고 Dock 접근을 유지합니다. 유효한 위치가 관측되면 안내와 Dock 아이콘을 숨깁니다. 유효한 template 이미지와 짧은 `CB` 표시는 아이콘 식별을 돕지만 실제 표시 성공을 보장하지 않습니다. macOS 26에서는 [시스템 설정 → 메뉴 막대의 앱별 표시 허용](https://support.apple.com/guide/mac-help/change-menu-bar-settings-mchlad96d366/26/mac/26)을 확인할 수 있습니다. 최종 설치본의 실제 아이콘과 Cinema Bar 자체 ON 항목, native 클릭·오른쪽 메뉴·종료 후 재실행을 직접 확인해야 합니다. Cinema Bar 항목이 목록에 없거나 아이콘이 보이지 않으면 Dock에서 앱을 여세요. 앱은 이 OS 설정이나 접근성 권한을 자동 변경하지 않습니다. 트레이 위치가 불확실하면 커서가 있는 화면 안으로 창을 배치합니다. 좌표·자동 smoke만으로 실제 메뉴 표시나 헤더의 포인터 드래그 성공을 대신하지 않습니다.

저장한 날짜와 포맷 안에서 아직 시작하지 않은 예매 가능 회차를 가장 이른 순서로 알려줍니다. `ALL`은 모든 포맷을 비교하고 같은 작품·극장·지정 날짜의 예매 오픈을 목적지별 한 번 알립니다. **가장 빠른 회차만 알림**을 선택하면 선택한 포맷의 가장 빠른 미래 회차 한 건을 날짜별 한 번 알립니다. 지정 포맷에서 선택을 끄면 기존 회차별 알림을 사용합니다. ALL의 두 선택 상태는 같은 완료 기록을 공유하며, 이후 더 빠른 회차가 나타나도 반복 알리지 않습니다. 카드에는 실제 회차 포맷과 시작 시각을 표시하고, 24–29시 영업일 시각은 다음 날 시각을 함께 안내합니다. 가장 빠른 회차 표시는 시작 시각에 만료되며 알려진 다음 미래 회차로 옮깁니다.

감시 카드의 배너에는 공식 영화 목록에서 확인한 포스터를 표시합니다. 이미지가 없거나 받지 못하면 기존 티켓 배너가 표시되며 저장된 감시를 다시 저장할 필요는 없습니다.
